## 1. 跨分区复制/移动：D1 单语句复制和事务性移动

### 修复之前的缺陷

`functions/utils/disk/core.js` 原来逐节点 INSERT，并在最后 DELETE 原始目录树。发生 D1 中断、写入冲突、进程终止时，可能留下部分目标子树；原来的手工反向删除不是原子回滚，且每个节点多次请求 D1。此前 2000 节点提前拒绝只降低超限概率，不覆盖中途故障。

### 实际修改

- 将复制的多节点操作合并为一个 `WITH RECURSIVE ... INSERT INTO disk_nodes ... SELECT` SQL 语句，实现单句原子性。
- 跨分区 **move** 使用 `D1Database.batch([copy,delete])` 事务执行，任何 SQL 语句失败时由数据库回滚整组；不再保留逐节点复制/尽力回滚的流程。保留同分区 move 的原有单句 UPDATE，继续阻止复制到自身的子目录。
- 虚拟新节点的 ID 用随机 UUID 前 28 字符 + `ROW_NUMBER() ... printf('%08x')` 构造，保证对同一目录多次复制后生成的 ID 仍固定 36 字符，且保持原层级父子映射。
- 新增目标真实目录存在检查、源树单句容量防线，仍以 2000 节点为单次操作上限；超过上限返回明确错误，不会部分写入。维持 `is_public=0`，仅复制物理 source_id 引用，不重上传也不删除 ImgBed 文件。
- `deploy/server/sqliteD1.js` 新增与 Cloudflare D1 类似的 `batch()` 模拟，使用 better-sqlite3 的事务机制。
- `test/disk.test.js` 增加：注入源树删除失败触发全事务回滚、目标同名冲突、同分区目录复制、连续复制节点 ID 长度不增长。对原有超限案例保留回归。

## 2. FolderSync S3 客户端兼容性：对象元数据和条件读取

- `functions/s3/[[path]].js` 对 GET/HEAD 设置 `Last-Modified`（虚拟节点 updated_at）；支持 `If-None-Match` 命中返回 304、`If-Match` 不匹配返回 412，不会消耗底层 R2 或 Telegram 对象内容。
- S3 网关和 Telegram 等 ImgBed 原生读取器的 ETag 不一定一致：由 S3 网关先判断虚拟 ETag，再删除发往底层的 `If-Range`，让匹配条件的 Range 继续产生 206，旧 ETag 返回完整 200。HEAD 忽略 Range。
- `test/s3-range-route.test.js` 增加原生/虚拟 ETag 不一致、HEAD、304/412、Last-Modified 的单元断言。
- `scripts/wrangler-disk-smoke.mjs` 增加真正 HTTP 的条件请求验证，且使用写源/写目标协同密钥实际调用跨分区嵌套目录移动并检查目标完整、原目录不再存在。
- 现有 GetBucketLocation、HeadBucket region、ListObjectsV2、Multipart 和 Path-style 配置保留。**Android FolderSync 真机的双向同步、时间戳策略、断网恢复尚未实测，不得记为通过**。
