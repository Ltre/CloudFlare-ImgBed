## 用户问题与审查范围

用户问「还有哪些功能未完成的？我提过的」。以最早的明确要求为依据：多级目录、路径面包屑、跨分区/跨协同文件及目录复制移动、S3 API、分区、协同、分享、静态文件公开、复用原 ImgBed 上传、可视预览、大文件 Range/分片预览、Cloudflare Workers 或 Pages 可部署。G0–G4 是后续验收合同，不能把所有未运行测试笼统归为“功能未开发”。

## 明确的功能覆盖不足

1. **网盘页面的大文件上传**：`frontend-dist/disk.html` 的文件选择器直接构造 FormData，单次 POST `/upload`，成功后 `/api/disk/import`。未在该页面调用 ImgBed 原有 `initChunked/chunked/merge` 客户端分片上传协议。需要复用原有流程；不重新设计上传引擎。
2. **S3 仅常用子集**：`functions/s3/[[path]].js` 已实现常见对象、SigV4、R2 Multipart 主要操作。但完整 AWS S3 的 CreateBucket/DeleteBucket/ACL/IAM/Versioning/Tagging/全部条件操作/特殊 streaming-checksum 模式尚未实现；显式已在 `docs/disk-cloudflare.md` 标为不交付范围。签名 SHA256 PUT/part 在 16MiB 后拒绝，需要 UNSIGNED-PAYLOAD 等兼容方式。若用户以原话要求广泛兼容，则功能仍不全，后续不能未经讨论把范围扩大为 AWS 全部服务。
3. **大目录跨分区复制移动可靠性限制**：`functions/utils/disk/core.js` 的 `transfer()` 一次最多约 2000 虚拟节点，创建失败后逐节点尝试删除；跨分区并非单事务。需明确上限和可恢复性，防止部分失败难处理。
4. **全渠道视频 Range/Seek**：R2 已有读取逻辑，其他 ImgBed 渠道通过原有读取器；各渠道大文件及浏览器媒体 Seek 没有真实验收，不能把未运行测试误记为已经证明不支持，也不应宣称全面支持。

## 已开发但尚待实测的功能

- D1 分区、多层目录、面包屑、文件/目录移动复制、读写协同密钥、跨分区多令牌、可撤销的文件与目录分享、逐文件静态公开、图片/视频/音频/PDF/文本预览。
- Cloudflare Pages/Workers 已有路由、绑定、迁移/部署配置；两个实际云环境未核验，不能声称已满足“保证可部署”。
- S3 第三方实际 SDK 接入未验证；Telegram/Discord 等真实密钥和分片/Seek 仍待 G3。

## 建议后续顺序

（1）网盘页大文件分片上传复用；（2）既有 S3 子集的第三方客户端兼容（不无限扩大范围）；（3）跨分区大目录移动复制失败恢复；（4）按用户明确指示，稍后再集中处理本地环境和 G1/G2/G3 测试。
